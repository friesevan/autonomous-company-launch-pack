    GitHub: the organization, the repositories, the machine user

    Who: either of you, on any computerAbout 30 minutes

    1. In the Launch Pack repository (friesevan/autonomous-company-launch-pack), open a pull request from day1-site-launch into main and merge it. Use this template copies only the main branch, so this comes before the next steps.

    2. Create a free organization at github.com/organizations/plan. Its name becomes the site's address before the company has a name, so pick something neutral, after the experiment rather than a brand. A custom domain can carry the brand later.

    3. Open the Launch Pack repository, then Use this template > Create a new repository: owner your-org, name company, Private. If the button is missing, tick Template repository in the Launch Pack's Settings.

      Then open the new repository's Actions tab once. If GitHub asks to enable workflows, enable them; the watchdog runs there.

      1. New repository, owner your-org, name your-org.github.io, Public, with Add a README ticked, so its main branch exists.
      2. Its Settings > Pages: Deploy from a branch, main, / (root), Save.

      The site stays private in practice until you approve it: the company pushes to it only after you set "publish": true (section 7).

      1. Sign out, and create a second, free GitHub account for the company, for example your-org-bot. It needs its own email; a plus address of the business email works (name+bot@…).
      2. As an organization owner: People > Invite member, the machine user, role Member. Accept the invitation as the machine user.
      3. In each of the two repositories: Settings > Collaborators and teams > Add people, the machine user, role Write.

      The company posts and replies from this account, so its comments are never confused with yours.

    6. Signed in as the machine user: Settings > Developer settings > Personal access tokens > Fine-grained tokens > Generate new token.

      • Name: company Mac mini. Resource owner: your-org. Expiration: as long as allowed.
      • Repository access: Only select repositories: company and your-org.github.io.
      • Repository permissions, read and write: Contents, Issues, and Variables (the heartbeat for the watchdog). Metadata is added as read-only. Nothing else: no Workflows, no Administration.

      Generate it and keep it at hand; you paste it on the Mac in section 6. If the organization requires approval, an owner approves it under the organization's Settings > Personal access tokens > Pending requests. Put the expiry date in your calendars: when it expires, the watchdog alerts you.

    7. In company on github.com, open investors/allowlist.md, edit it, replace the two bracketed lines with your GitHub usernames (one per line, no @), and commit. Only these accounts can instruct the company.

    8. In company: Issues > Labels > New label, name emergency. The Day 1 session creates all the labels anyway; making this one now lets the watchdog test in section 6 use it.

      1. Install the GitHub app and sign in with your own account.
      2. Open company, tap Watch, choose All activity.
      3. In the app's notification settings, turn on push for Participating and Watching; in iOS Settings, allow GitHub notifications.

      This is how emergencies, urgent requests, and reports reach you, at any hour for emergencies.

    3

    The Mac mini: macOS

    At the Mac, with a keyboard and displayAbout 30 minutes

    Everything from here on happens in the company's macOS account. Plug in Ethernet if you can.

    1. On a freshly erased Mac, the setup assistant creates it: name it, for example, company. At the Apple Account step choose Set Up Later, and skip iCloud, Siri, and Screen Time. If the Mac already has another account, add this one in Users & Groups as an Administrator and sign in to it. Keep no personal data on this Mac.

    2. System Settings > General > Software Update: install everything offered, and restart. The current Xcode needs a current macOS, and macOS 26 or later lets you unlock FileVault over SSH.

    3. Same pane, the ⓘ beside Automatic Updates:

      • On: Check for updates, Download new updates when available, Install Security Responses and system files.
      • Off: Install macOS updates and Install application updates from the App Store. A surprise restart or Xcode update mid-month can stop the company until someone is at the Mac.

    4. General > Date & Time: set the time zone to New York, so the Mac's logs match the reports' times.

    5. Privacy & Security > FileVault: turn it on, and keep the recovery key in your password manager, not on the Mac. Network > Firewall: turn it on. The company checks both every 15 minutes and alerts you if either is switched off.

    6. Energy: turn on Prevent automatic sleeping when the display is off, Wake for network access, and Start up automatically after a power failure. Lock Screen: Start Screen Saver when inactive, Never.

      With FileVault on, after any restart the Mac waits at its password screen and nothing runs until someone unlocks it. The watchdog tells you within about an hour; section 8 shows how to unlock it over SSH.

    7. General > Sharing: turn on Screen Sharing and Remote Login, and for each choose Allow access for Only these users: the company account. Note the Local hostname at the bottom of that pane and type it in the box at the top of this page.

    8. In Terminal, run these three lines. The first asks for the account password once.

      echo "$(whoami) ALL=(ALL) NOPASSWD: ALL" | sudo tee /etc/sudoers.d/company >/dev/null
sudo chmod 440 /etc/sudoers.d/company
sudo visudo -cf /etc/sudoers.d/company

      Expect parsed OK. Then check that sudo no longer asks:

      sudo -k; sudo -n true && echo "sudo works without a password"

      This was your choice, and it carries a risk: a web page the company reads could try to steer a session into admin commands. The guard hooks refuse the commands that would weaken security, every sudo command is logged, the posture check notices a protection switched off, and the watchdog runs outside the Mac. With passwordless sudo, nothing on the Mac is tamper-proof.

    9. Only if you have a spare drive. The company pushes everything that matters to GitHub after every run.

    The Mac mini: software

    At the Mac, in TerminalAbout 1 to 2 hours, mostly Xcode downloading
      1. Open the App Store app, Store > Sign In, with the developer Apple Account. Sign in to the App Store only, never iCloud.
      2. Install Xcode. It is large; start it now and continue with the next steps while it downloads.
    2. /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

      When it finishes, it prints the lines that put Homebrew on the PATH. Run them:

      echo >> ~/.zprofile
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"
      brew install gh jq
      1. Open Xcode once, agree to the license, and let it install its components.
      2. Xcode > Settings > Components: install the iOS platform and the current iOS Simulator runtime. One runtime is enough.
      3. Settings > Accounts, the + button, Apple Account: add the developer Apple Account. It asks for a two-factor code once.

    4. After Homebrew, because its installer can switch them to a separate Command Line Tools package:

      sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
sudo xcodebuild -license accept
xcodebuild -runFirstLaunch
    5. curl -fsSL https://claude.ai/install.sh | bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zprofile

      Open a new Terminal window, then check the version. It must be 2.1.293 or later.

      claude --version

    6. Claude Code's docs say a future release will change how headless runs start, which would break the run loop. The company updates deliberately instead, and smoke-tests each new version first.

      mkdir -p ~/.claude
test -f ~/.claude/settings.json || echo '{"env": {"DISABLE_AUTOUPDATER": "1"}}' > ~/.claude/settings.json
cat ~/.claude/settings.json
claude doctor | grep -i "auto-update"

      Expect disabled. If the file already existed without that env entry, add it by hand.

    7. Run claude, follow the browser sign-in with the company's Claude Max (20x) account, then type /exit. Use an account nobody uses for anything else: personal chats would eat the company's limits.

    5

    The Claude account

    On claude.ai, signed in as the company's accountAbout 10 minutes

    1. Settings > Usage: leave usage credits switched off. With them off, reaching a limit pauses work instead of billing. The company reads the plan's meter every 15 minutes and alerts you if they are ever switched on.

    2. The plan includes $200 a month of API credits. The company uses them only while a plan limit has paused work: never Fable, at most $50 a week, and never past $190 a cycle. Skip this step and overflow simply stays off.

      1. Settings > Billing: link a Claude Console organization.
      2. In the Console, create a workspace for the company and set its monthly spend limit to $180: a hard cap that holds even if the company's own count is wrong. Leave auto-reload off and buy no credits.
      3. Create an API key in that workspace. On the Mac, store it in the Keychain; the command asks for it twice:
      security add-generic-password -s company-api-credits -a company -T /usr/bin/security -w

      Sessions can't read it: the permission rules and the security guard block that. To turn overflow off later, set api_overflow to false in investors/billing.json on github.com.

    The Mac mini: GitHub, the repository, the tests

    At the Mac, in TerminalAbout 30 minutes
    1. gh auth login

      Choose GitHub.com, HTTPS, answer Yes to authenticating Git, choose Paste an authentication token, and paste the machine user's token. Then:

      gh auth setup-git
gh auth status

      Expect Logged in to github.com account your-org-bot.

    2. Its noreply address is in the machine user's GitHub Settings > Emails.

      git config --global user.name "your-org-bot"
git config --global user.email "ID+your-org-bot@users.noreply.github.com"

    3. In the home folder, not Desktop or Documents: macOS blocks background jobs from those folders.

      cd ~ && gh repo clone your-org/company && cd company
ls -l tools/supervisor.sh rules/hooks/security-guard.py

      Both lines start with -rwx. If not: chmod +x rules/*.py rules/*.sh rules/hooks/* tools/*.sh tools/*.py tests/*.sh tests/*.py, then commit and push.

    4. Apple still pending? Skip this step for now. Do it once Apple approves the membership and you've created the key, then tell the company in a comment on any issue.

      Move the .p8 file from section 1 into place, and record the three IDs in a file git ignores:

      mkdir -p ~/.appstoreconnect/private_keys
mv ~/Downloads/AuthKey_*.p8 ~/.appstoreconnect/private_keys/
cat > ~/company/ops/secrets.local <<'EOF'
ASC_KEY_ID=your-key-id
ASC_ISSUER_ID=your-issuer-id
APPLE_TEAM_ID=your-team-id
EOF

      Then open ~/company/ops/secrets.local in TextEdit and replace the three values.

    5. A few minutes, no Claude usage, nothing sent anywhere:

      tests/run.sh

      Expect All tests passed.

    6. In ~/company, run claude, choose Yes, I trust this folder, then type /exit. Headless runs use the project's allow rules only after this.

    7. One tiny real run with the run loop's own flags. It costs about a cent of usage.

      tools/smoke_test.sh

      Expect six PASS lines: the version, a session ran, billed to the subscription, auto mode, the hooks ran, and CLAUDE.md loaded. A FAIL line prints what to fix.

    8. tools/heartbeat.sh && gh variable list

      Expect a HEARTBEAT_AT line with the current time. If it fails, the token lacks the Variables permission.

    9. On github.com, in company: Actions > Watchdog > Run workflow, tick test, and run it. Within a minute or two you both get a notification for "Watchdog test: you can ignore this", and the issue closes itself.

      The watchdog runs every 30 minutes on GitHub's servers. Once Day 1 has started, it opens an emergency if the Mac goes 45 minutes without a heartbeat, and closes it when the Mac is back.

    After Day 1: what you'll use

    Keep this for the month
    Answering a report
    Comment on its issue: plain language works, or "1: A", "APPROVE 3", "REJECT 2: too busy". Answer as often as you like; your latest answer counts, and one that comes after a default still counts. Every message gets a reply saying what the company understood, or a short automatic receipt if it can't reply right away.
    Messaging the company
    Open a new issue in company (the directive label is suggested) or comment on any issue. It reads every message from your accounts within about 15 minutes.
    Pausing and resuming
    Start a comment or a new issue with PAUSE or STOP. Within about 5 minutes nothing runs, even in the middle of a session, and it confirms in the thread. RESUME restarts it the same way.
    "The company has stopped: no heartbeat from the Mac mini"
    The watchdog's emergency. Check, in order: a restart or power cut left the Mac at the FileVault screen (unlock it at the Mac, or from a computer on the same network with ssh company@company-mac-mini.local and the account password); the network; an expired GitHub token (make a new one, then gh auth login on the Mac); or a stopped run loop (tail -50 ~/company/ops/runs/supervisor.log). The issue closes itself when the heartbeat returns.
    Other emergencies
    Claude Code logged out (run claude, then /login), runs failing three ticks in a row, a security setting switched off, a session that changed your files (the supervisor puts them back), an amendment that doesn't quote your message word for word (it's removed), usage credits found on, or a new Claude Code version failing its smoke test (the company pauses itself; fix it, then reply RESUME).
    Following along
    The site's Usage page shows the plan's limits, the plan by now, and why the company is ahead or behind. Its Subscribe page lists three feeds for a feed reader: reports, product updates, and the records.
    When it ends, or for a long pause
    Turn off the watchdog: in company, Actions > Watchdog, the ⋯ menu, Disable workflow. Then stop the loop on the Mac: launchctl bootout gui/$(id -u)/com.company.supervisor.
    The full guides are in the company repository: setup/INVESTORS.md (this setup, with the reasons), setup/APPLE.md, and setup/OPERATIONS.md.
